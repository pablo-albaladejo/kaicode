0Architecture

1Launch

claude is a zsh function (~/.zshrc, block claude-gateway). It loads ~/.claude/aircall-gateway.env (gateway URL, model aliases, limits), reads the gateway key live from ~/.aircode/config.json, clears CLAUDE_CONFIG_DIR, and starts the binary. Every session goes through https://api.llmgateway.io and is traced in Langfuse.

claude                              # primary agent: lead · model: fireworks/deepseek-v4.1-flash · high
claude @ticket APR-1234 [slug]      # fetch, ff main, worktree ../<repo>.wt/APR-1234 on feat/APR-1234, then claude there
/ticket APR-5678 [slug]             # inside a session: prepare that ticket's worktree; then `claude @ticket APR-5678` in a new terminal (cd does not persist)
claude @pick                        # fzf over all 79 gateway models (id · in · out · cache · group), then --model
claude @strong  ·  @mid:2  ·  @gpt-6-sol   # group (models.json), Nth of a group, or any model id
claude @solo                        # primary agent "solo": all tools, can edit files itself
claude @ticket APR-1234 @solo --continue   # combine freely; extra args go to claude
GUARD_BRANCH=off claude             # one session without the main-branch guard
cc-models          cc-models --list          cc-cost --days 7 --all
VS Code's extension starts the binary directly, without the zsh function. It picks up settings.json (agent, hooks, statusline) but not the .env; if it shows a Sonnet model or no statusline, check the process environment (section 9).

Agent vs skill vs command

  • Agent: "someone does X and returns Y" (own context, model, tools).
  • Skill: "when you do X, do it this way" (knowledge in the current context; auto-loaded).
  • Command: "I start X with these args" (/name, a flow the user controls).

Model · effort variants

  • gen-effort-variants.mjs reads the router table and writes <role>--<alias>-<effort>.md for the 5 subagents: same prompt, frontmatter model: (gateway id) + effort:. 5 roles × 10 (model, effort) pairs = 50 files.
  • The router only swaps subagent_type to that variant; it never sets model (the Agent tool rejects anything but sonnet|opus|haiku|fable there). Never launch variants by hand.
  • Re-run after editing a base agent or the table; --clean removes them. cc-cost and the statusline group them under the base role.

Read shunt (cheap reads for expensive agents)

  • Reading is I/O, not thinking. An agent on sol/opus/pro that Reads a file > 350 lines whole is denied by hooks/read-shunt.mjs and told to run node ~/.claude/tools/bulk-read.mjs "<question>" <files…>.
  • bulk-read sends the files (numbered, XML-wrapped) to deepseek-v4.1-flash through the gateway and prints cited bullets; the expensive agent pays for the answer only (~90% less on big reads, Spotify's shunt result). Windowed Reads (offset+limit) always pass, for quoting and editing.
  • Cheap agents (flash, luna) and the lead read directly. Not for editing or judgement: line numbers are for locating, verify with a small Read.
  • Limits: ≤ 3 subagents in parallel, spawn depth 1 (subagents never launch subagents; bulk-read is a plain call, no slot).

code-write (cheap output for mechanical files)

  • Output tokens are the expensive ones. An implementer on pro/sol can describe a mechanical file (fixtures, table tests, migrations, types from a schema, a module mirroring another) and let flash write it: node ~/.claude/tools/code-write.mjs "<spec>" --out <new file> --ref <file to imitate>. The agent never reads the result: tests, linter and git diff --stat verify it.
  • Guard rails: refuses on main/master; new files only unless --overwrite; specs under 40 chars refused; bash-guard denies it to every agent but implementer--pro|sol-* (codeWriteAgents). Never for business logic or security-sensitive code.
  • code-write --report: files kept as generated vs edited afterwards, the metric that says whether delegating the write pays off.

5Git workflow

claude @ticket <T> [slug]

  • git fetch --prune origin
  • Fast-forward local main to origin/main (refuses on divergence)
  • Worktree ../<repo>.wt/<T> on feat/<T>[-slug] from origin/main; reuses an existing branch or worktree
  • Copies gitignored files listed in <repo>/.worktreeinclude (e.g. .env)
  • Starts claude inside

guard-branch hook

  • PreToolUse on Edit/Write/NotebookEdit
  • Denies edits on main/master or in the main working tree; the agent gets the reason
  • No-op outside a git repo; GUARD_BRANCH=off for one session
  • Config: ~/.claude/guard-branch.json (protected, requireWorktree)

deny rules (settings.json)

  • git push --force / -f, git branch -D, git checkout|switch main
  • rm -rf /, rm -rf ~
  • glab mr approve|merge|close|update
  • aws-vault with prod profiles stays allowed on purpose
git worktree list                                   # what is checked out where
git worktree remove ../conv-ai-settings.wt/APR-1234  # after the MR is merged

6MR review

/review-mr !123                # someone else's MR: blockers, posted inline · your own MR: full, chat only + offer to fix
/review-mr !123 --full         # force full (+ Minor, Question, Suggestion) · --blockers forces blockers
/review-mr !123 --spec         # also compare with the OpenSpec change
/review-mr [--post|--no-post]  # current branch vs main; --post/--no-post override the own/other default
/review-mr https://gitlab.com/aircall/.../-/merge_requests/123   # from any folder
target → mr-checkout.sh (URL: find/clone repo under ~/development, worktree ../<repo>.wt/mr-<iid>) → reviewer (JSON) → chat summary → mr-post.mjs → one inline discussion per finding

What gets posted

  • Only inline discussions on path:line in Changes; no general notes. Verdict and summary stay in the chat.
  • Body: **Severity** — message + "Proposed fix" snippet + hidden marker <!-- cc-review:hash -->
  • Re-runs skip findings already posted (marker). Lines outside the diff move to the nearest diff line ("about line N"); files outside the diff are reported as not_posted.

Style (reviewer prompt)

  • English B1, short, direct, actionable, one idea per finding
  • Humble, as a question or proposal: "Could we…?", "Would Z work?"
  • No praise, no restating the diff, no "nit:"; ≤ 12 findings
  • Never glab mr note|approve|merge|update

7Costs & monitoring

Claude Code's own $ (/usage, --output-format json) is only right for Anthropic ids. For gateway models it logs unrecognized_model and inflates ×3–×24. cc-cost and the statusline are the reference: they price from ~/.claude/pricing.json (209 entries: 79 models, with and without provider prefix; lookup exact → without date suffix → without provider).

Floor per API call is ~14k input tokens (system prompt + tools): ~$0.0002 on Flash with cache, ~$0.003 on Opus. That is why the primary stays on Flash and strong models are reserved for subagents. Langfuse (gateway side) is the source of truth for billing; Jev calls go through your own LLM Gateway org, not Aircall's traces.

10Security & conventions

Keys

  • Only in env vars / aircode config; never in JSON config files
  • Rotate any key that was pasted in a chat (two LLM Gateway keys and the aircode key were)
  • ~/.aircode/config.json.bak-* contains a plaintext key: delete after rotating

Permissions

  • bypassPermissions is on; deny rules are the hard guarantees; guard-branch covers edits
  • "auto" mode is not available with non-Anthropic models via gateway
  • Writes to GitLab/Jira beyond /review-mr need confirmation in chat

Conventions

  • Everything configured is in English
  • Gateway ids only, never haiku/sonnet/opus aliases
  • Subagents return summaries, never diffs; implement → review ≤ 2 rounds
  • Briefs start with the kind of work (read-only / lookup / plan / change / review): it is what the router classifies
  • Change one model alias in router.json models to A/B it across all its cells; measure with cc-cost before changing the table

11Agentic SDLC · /ship (phase 1)

The full design (three levels: /design → /plan → /ship, knowledge layer, deciders, flow conditions) lives in the Agentic SDLC artifact. Phase 1 implements the ticket loop.

/ship APR-1234                 # prepare → understand → plan → review-plan → implement → review-code → STOP → open MR → pipeline → review-mr → close+learn
/ship APR-1234 --status        # stage, attempts, verdicts, MR, cost
/ship APR-1234 --reset         # archive the state and start over · --from <stage> · --budget <usd>
node ~/.claude/tools/ship-state.mjs list | status | get APR-1234    # the state machine store (also what the hooks read)
node ~/.claude/tools/cc-cost.mjs --ticket APR-1234                  # spend attributed to the ticket (its worktree/branch sessions)

State

  • <worktree>/.claude/ship/<T>/state.json (git-excluded): stage, attempts per gate, verdicts, MR, pipeline, cost, lessons, history. Plus brief.md, plan.md, mr.md.
  • Resumable: /ship <T> reads it first; a compaction or a new session does not lose the loop.
  • Runs only in a session started in the ticket's worktree; from elsewhere it prepares the worktree and stops with claude @ticket <T>.
  • HUD line 2: ship:<stage>#<attempt> $cost/budget, red with STOP when waiting for you.

Gates and stops

  • Fact gates as hooks (ship-gates.mjs): implementer must report Status: done · Tests … failed 0 · Lint: clean (one bounce, then recorded); glab mr create / git push need verdicts.code = APPROVE.
  • Judgement gates: reviewer JSON (review plan:, code, MR); no Critical/Major to pass.
  • ≤ 2 rounds per gate, ≈ $5 per ticket (shipBudgetUsd, shipMaxAttempts); beyond → STOP and ask.
  • Human STOPs: open questions (once), high-risk plan, before the MR, Jira writes, merge (always).

Contracts

  • investigator understand: → Acceptance criteria, Touches, Open questions with defaults.
  • planner → Risk, Files, steps with done when, Covers (criterion → step).
  • reviewer review plan: → same JSON, path: "plan", line = step.
  • Learn at close: ≤ 3 lessons → repo docs/codebase-map.md Gotchas (in the MR), ~/.claude/knowledge/lessons.md, or process.md for /retro.

Next phases: /map + knowledge index (2), /plan + /epic (3), /design (4), /retro (5).
