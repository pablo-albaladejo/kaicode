## Purpose
Terraform-defined Datadog monitors (Lambda throttling/errors, API Gateway 5XX, SQS/DLQ) for the **conv-ai-settings** service, owned by the voiceai/agent-productivity team. It is infrastructure config, not an application: no runtime code, no tests.

## Layout
- `modules/monitors/` — the domain logic: reusable `datadog_monitor` resources, one `.tf` file per infrastructure component (`lambda.tf`, `apigateway.tf`, `sqs.tf`, `azure.tf`), plus `variables.tf` and `README.md` (generated by `terraform_docs`).
- `environments/production/` — Terraform root: remote backend, AWS/Datadog providers, module invocation; workspace `conv_ai_settings_monitors_production_pdx_app`.
- `environments/staging/` — same shape for staging; workspace `conv_ai_settings_monitors_staging_pdx_app`.
- `modules/dashboard/` — Datadog dashboard resources (not described in AGENTS.md/CLAUDE.md).
- `.gitlab/ci/` — per-environment pipeline definitions (init, validate, plan, deploy) included by the root pipeline.
- `.gitlab/merge_request_templates/` — `default.md` MR template.
- root — `README.md`/`readme.md` (duplicate), `AGENTS.md`, `CLAUDE.md`, `.gitlab-ci.yml`.
- Entry points are the environment roots (`environments/*/main.tf`); there are no tests anywhere in the repo.

## Run · test · lint
```
terraform fmt -check -recursive          # format check (repo root)
cd environments/staging && terraform init && terraform validate
cd environments/production && terraform init && terraform validate
terraform plan                            # from an initialized environment root
```
No test suite exists — there is no command to run one test file (not stated).

## CI / deploy
Stages, in order: `init` → `validate` → `quality` → `security` → `plan` → `deploy`.
- Root `.gitlab-ci.yml` includes remote templates `terraform-template.v2.yml`, `iac-policies.v1.yml`, `security.main.yml`, plus local `.gitlab/ci/*.yml`; default runner tag `aircall-eks-shared-default`, `GIT_STRATEGY: clone`.
- Pipelines run on MR (`$CI_MERGE_REQUEST_IID`), on push/merge to the default branch, and on web-triggered manual pipelines.
- Staging and production deploy independently; deploy jobs are manual (`when: manual`) on the default branch. Production uses runner tag `aircall-eks-shared-production`.
- Changes to `modules/**/*` trigger both environment pipelines. On a tag: not stated.

## Data
No databases, no ORM, no migrations folder (`migrations: none`). State lives in Terraform Cloud remote backend, org `aircall`, one workspace per environment (`conv_ai_settings_monitors_{production,staging}_pdx_app`). AWS auth is assume-role via Terraform Cloud; Datadog credentials come from Terraform Cloud workspace variables. How state/migrations are applied per environment beyond the manual deploy job: not stated.

## Conventions
- Terraform ~> 1, Datadog provider ~> 3.29.0, AWS provider ~> 5.
- Run `terraform fmt` before committing; pre-commit hooks: `terraform_fmt`, `terraform_validate`, `terraform_tflint`, `terraform_docs`.
- One `datadog_monitor` resource per logical alert, grouped by component in separate `.tf` files; locals for thresholds/prefixes at the top of each file; `for_each` over a local list for repeated monitors (e.g. SQS queues).
- Monitor naming: `[Conv AI Settings][Component] ${var.env}: description`; always include `var.notify_channels` in the message.
- Tags: `setunion(local.tags, ["env:${var.env}", "service:${local.service}"])`; base tags include `team:agent-productivity`, `source:terraform`.
- DLQ monitors wrap queries in `default_zero()`.
- New variables go in `modules/monitors/variables.tf` and must be passed from both environment roots.
- Commit messages: concise, describe the monitor change (e.g. "Add API Gateway 5XX monitor"). MR template at `.gitlab/merge_request_templates/default.md`. No CODEOWNERS.
- Never commit AWS credentials or Datadog API keys.

## Where to start
- Bug in an existing alert (wrong threshold, noisy/quiet monitor) — `modules/monitors/lambda.tf` or `modules/monitors/apigateway.tf` (the resource and its locals), then `modules/monitors/variables.tf` for the threshold inputs.
- Alert not firing in one environment — `environments/staging/main.tf` / `environments/production/main.tf` (module invocation, `env`, `notify_channels`), then `.gitlab/ci/` for whether deploy ran.
- New monitor for a new component — `modules/monitors/variables.tf` (add inputs), a new `modules/monitors/<component>.tf`, then both `environments/*/main.tf` to pass the variables.
- Notification channel / routing change — `README.md` (Datadog Slack integration steps) and the `notify_channels` value in each environment root.
- Pipeline or deploy failure — `.gitlab-ci.yml` (includes, stages, workflow rules) and `.gitlab/ci/*.yml`.
